# Documentation Architecture v2

## Status

Mandatory from Phase 09 through the final project phase.

## Objectives

Documentation Architecture v2 makes project knowledge discoverable, non-duplicated, reviewable, and maintainable as the platform grows.

## Document Classes

1. Entry points: root README, roadmap, changelog, contributing, architecture, and release checklist.
2. Canonical references: architecture, database, accounting, security, development, glossary, and vision documents.
3. Historical records: phase documents and release notes.
4. Decision records: ADRs.
5. Registries and dictionaries: module, architecture decision, database, and domain indexes.
6. Templates and checklists: repeatable delivery controls.

## Mandatory Maintenance Contract

Every phase must update all affected canonical documents, registries, dictionaries, ADRs, roadmap status, changelog, and validation evidence in the same pull request.

## Automated Index

`docs/index.md` is generated by `scripts/generate-doc-index.mjs`. Contributors must run the generator after adding, moving, or deleting documentation files. CI checks that the generated index is current.

## Traceability

Every major feature must be traceable across:

- roadmap phase;
- phase document;
- module registry entry;
- relevant ADRs;
- database objects and migrations;
- permissions;
- tests and validation evidence;
- changelog and release record.

## Non-Duplication Rule

Normative rules belong in one canonical document. Phase documents describe changes and link to the canonical rule. ADRs explain why a decision was made.
